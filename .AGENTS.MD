# api-laravel-54 - Proyecto de Integración Hotelera

Este proyecto actúa como un middleware entre canales de reserva (OTAs como Booking.com, HotelBeds, Expedia) a través de **RateGain** y el sistema de gestión hotelera **Bamboo**.

## Tecnologías
- **Framework:** Laravel 5.4
- **Lenguaje:** PHP 7.x
- **Base de Datos:** MySQL (con conexiones dinámicas)
- **Protocolo:** XML (OTA_HotelResNotifRQ / RS)

## Arquitectura y Componentes Clave

### 1. Conexiones "On The Fly"
El proyecto gestiona múltiples hoteles. La conexión `on_the_fly` se configura dinámicamente basándose en el `HotelCode` recibido en el XML.
- Modelo de configuración: `App\BambooInstance`
- Lógica de conexión: `App\Http\Controllers\XMLController::getInstance()`

### 2. Procesamiento de XML (`App\Rategain\Rategain`)
Es el núcleo de la lógica de negocio. Se encarga de:
- **Reserva (`saveReservation`):** Valida existencia, asigna habitaciones, crea clientes, folios, cargos y planes de tarifa.
- **Disponibilidad (`sendAvailability`):** Calcula y envía el inventario real a RateGain.
- **Modificaciones y Cancelaciones:** Gestiona el ciclo de vida de la reserva.

### 3. Sanitización y Parsing
- El XML entrante se limpia de emoticonos y caracteres de control en `XMLController::removeEmoticon`.
- `XMLController::xmlToArray` convierte el XML a un array plano, incluyendo atributos, para facilitar el acceso a los datos.

## Reglas para el Agente

### Base de Datos
- Al interactuar con modelos de hotel (Reserva, Folio, Habitacion, etc.), asegúrate de que la conexión sea `on_the_fly`.
- Los contadores (`numres`, `numfol`, `codcan`) deben obtenerse mediante `MAX() + 1` de la base de datos específica del hotel.

### Lógica de Negocio
- **Atomicidad:** Utiliza transacciones de DB en procesos complejos como `saveReservation`.
- **Flexibilidad XML:** Considera que los elementos del XML pueden ser objetos (si es uno solo) o arrays (si son varios). Usa `ensureArray()` y `getString()` definidos en `Rategain.php`.
- **Referencia Única:** El ID de referencia de la OTA es sagrado y debe guardarse en `reserva.referencia` para evitar duplicados en estados `Commit`.

### Debugging
- Errores críticos en la integración RateGain deben registrarse en `storage/logs/rategain_error.log` con el mensaje y el stack trace.
- Siempre devuelve una respuesta XML válida (`OTA_HotelResNotifRS`) incluso en caso de error.
